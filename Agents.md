# Agent Notes

## Repo shape

- pnpm workspace with three real packages: `packages/contract` (`@activitypub-relay/contract`), `packages/relay` (`@activitypub-relay/relay`), and `packages/frontend` (`@activitypub-relay/frontend`). Root scripts often use short filters (`relay`, `frontend`); scoped filters also work.
- Contract-first API flow: edit `packages/contract/src/index.ts` first, implement matching handlers in `packages/relay/src/api/router.ts`, then call through the frontend ORPC client in `packages/frontend/src/composables/useApiClient.ts`.
- Relay entrypoint is `packages/relay/src/server.ts`. It wires Hono routes for ActivityPub/WebFinger/NodeInfo/static assets and mounts ORPC via `OpenAPIHandler(router)` under `/api` with `prefix: '/api'`.
- Backend DB access goes through `createDb(env.DB)` in `packages/relay/src/lib/db.ts`; Drizzle table definitions live in `packages/relay/src/db/schema.ts`.
- Frontend Vite root is `packages/frontend/src`, not the package root. Pages are auto-discovered from `src/pages/*/index.html`.

## Commands that matter

- Install: `pnpm install`.
- Dev all: `pnpm dev` (runs relay + frontend concurrently). Individual: `pnpm dev:relay`, `pnpm dev:frontend`.
- Relay dev script is `wrangler dev src/server.ts -e development`; Wrangler's default port is 8787. The frontend dev server is port 5173 and proxies API/ActivityPub paths to `http://localhost:8787`.
- Build/deploy: `pnpm build` builds only the frontend; output is written into `packages/relay/public`. `pnpm deploy` runs frontend build, then relay deploy (`wrangler types && wrangler deploy --minify src/server.ts`).
- Code quality: `pnpm check` (`oxfmt` + `oxlint`), `pnpm fix`, `pnpm fix-unsafe`.
- DB: `pnpm db:generate` runs Drizzle Kit migration generation; local migrations `pnpm db:migrate`; production migrations `pnpm db:migrate:prod`.

## Tooling and generated files

- `worker-configuration.d.ts` is generated by `wrangler types`; do not hand-edit it. If Worker Env/D1 bindings change, regenerate types before trusting TypeScript diagnostics.
- There is no configured test script or typecheck script in `package.json`. If adding verification commands, make that explicit rather than assuming `pnpm test` or `pnpm typecheck` exists.
- Root `tsconfig.json` is strict, `noEmit`, bundler resolution, and allows TS extension imports. Package aliases map `@/*` to each package's own `src/*`.

## Environment and secrets

- Local relay env lives in `packages/relay/.dev.vars` copied from `packages/relay/.dev.vars.example`; set `PUBLICKEY`, `PRIVATEKEY`, and `API_KEY` there.
- Production secrets must be registered with Wrangler (`wrangler secret put PUBLICKEY`, `PRIVATEKEY`, `API_KEY`). Do not put these secrets in `wrangler.toml`.
- `packages/relay/wrangler.toml` owns `HOSTNAME`, D1 binding `DB`, and the Workers Assets binding `ASSETS` pointing at `packages/relay/public`.

## Frontend/build quirks

- `packages/frontend/vite.config.ts` builds directly into `../relay/public` and empties that directory. The custom plugin moves `pages/index/index.html` to `index.html` and `pages/admin/index.html` to `admin/index.html` after build.
- Static asset serving in `server.ts` appends `index.html` for extensionless paths, so `/admin` and `/admin/` rely on the built `public/admin/index.html`.
- API clients send `X-API-Key` from localStorage; backend `/api/*` rejects missing or mismatched keys.

## Existing docs caveats

- `README.md` and `development.md` contain useful setup/deploy notes, but some prose is stale or generic. Trust executable config first: current relay dev port is Wrangler's 8787, while the frontend proxy also targets 8787.
- `development.md` mentions directories like frontend `router/` and `api/` that are not present in the current source tree; current frontend API wiring is in `src/composables/useApiClient.ts`.
